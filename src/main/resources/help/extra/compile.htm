Compiling with Ahk2Exe

Ahk2Exe, the compiler of AutoHotkey, turns a script into an executable (.exe) that runs without an AutoHotkey installation. The plugin calls Ahk2Exe in the background and shows its output in the IDE.

Requirements

  • Ahk2Exe installed, normally as Compiler\Ahk2Exe.exe in the AutoHotkey folder. If it is missing, start AutoHotkey Dash from the Windows Start menu and click Compile, which installs it. The plugin finds it by itself; otherwise set the path under Settings.
  • The script names its base file with a line ;@Ahk2Exe-Base. The base file is the AutoHotkey interpreter that becomes part of the executable; it decides the AutoHotkey version and 32 or 64 bit.

Prepare a script

Ahk2Exe reads its settings from special comments in the script, the ;@Ahk2Exe- directives (see "Script Compiler Directives" in the AutoHotkey help). A typical head:

#Requires AutoHotkey v2.0
;@Ahk2Exe-Base ..\v2\AutoHotkey64.exe
;@Ahk2Exe-SetMainIcon app.ico
;@Ahk2Exe-SetProductName Clipboard Tool
;@Ahk2Exe-SetVersion 1.2.0
;@Ahk2Exe-SetCopyright (c) Example Ltd.
  • A relative path in ;@Ahk2Exe-Base is relative to the folder of Ahk2Exe.exe: ..\v2\AutoHotkey64.exe is the 64-bit interpreter of a standard installation. The older form ;@Ahk2Exe-Bin is accepted as well.
  • The line must start at the beginning of a line, in the main script.
  • Without it the plugin compiles nothing; a notification offers Add Ahk2Exe directives (see below). Reason: Ahk2Exe would otherwise use the base file last chosen in its own window, which may be one of AutoHotkey v1, and every v2 script would fail.
  • Everything else (name and folder of the executable, icon, version information) comes from the directives. By default the executable is created next to the script with the same name.

Insert a head of directives

In a script without ;@Ahk2Exe-Base, Alt+Enter anywhere in the file offers Add Ahk2Exe compiler directives. The same is offered by the notification that appears when Compile with Ahk2Exe finds no base directive. It inserts this head below the #Requires line (without one, at the start of the file):

#Requires AutoHotkey v2.0
;@Ahk2Exe-Base ..\v2\AutoHotkey64.exe
; ---------------------------------------------------------------------------
;@Ahk2Exe-SetProductName    tool
;@Ahk2Exe-SetVersion        1.0.0
;@Ahk2Exe-SetDescription    tool description
;@Ahk2Exe-SetLanguage       0x0409
;@Ahk2Exe-SetCopyright      © 2026 Your Name
;;@Ahk2Exe-SetMainIcon      tool.ico
;;@Ahk2Exe-ConsoleApp
; ---------------------------------------------------------------------------
  • The placeholders (product name, version, description, copyright) are selected one after another; type the value and press Tab for the next one, Enter or Esc to keep the rest. The name defaults to the file name.
  • The base file is AutoHotkey64.exe, or AutoHotkey32.exe if #Requires asks for 32-bit.
  • Write the values without quotes: Ahk2Exe takes the rest of the line as it is, quotes would appear in the properties of the executable. Spaces are fine; a comma must be written as `,; a comment after the value needs a space before the ;.
  • ;@Ahk2Exe-SetVersion sets file and product version. Set Version... changes this line in all scripts of the project for you, with commit and version tag. If the script already has such a line (for example one that Set Version added), the head takes it over: the line is removed and its version becomes the default.
  • Lines starting with ;;@ are disabled directives. Remove one ; to set an icon or to build a console application.
  • 0x0409 is the language code for English (United States), e.g. 0x0407 for German.

Compile

Code > Compile with Ahk2Exe, or the context menu of the editor or of the project view.

  1. The script is chosen like for the validation: the script of the AutoHotkey run configuration selected in the toolbar, from whatever file is open, otherwise the current file.
  2. All modified files are saved (not only AutoHotkey files).
  3. The plugin runs Ahk2Exe.exe /in script /compress n /silent verbose in the folder of the script, as a background task that can be cancelled.
  4. The console in the Run tool window shows "Compiling name.ahk...", the output of Ahk2Exe and a summary: green "Ahk2Exe created path", or red with the exit code. Errors in the script have a link to the file and line.

Compile and run

A run configuration can compile the script first and run the executable instead of the script. Turn on Compile with Ahk2Exe and run the executable in the configuration. This is meant for console applications (;@Ahk2Exe-ConsoleApp): a compiled console application gets a real console, a script run by AutoHotkey does not.

Run the executable in chooses where:

ChoiceBehavior
Terminal in the Run tool windowDefault. A pseudo console inside the IDE: ANSI escape sequences (colors, cursor movement), keyboard input and the console functions work. The output of Ahk2Exe is shown above the output of the program.
Separate console windowA normal Windows console window, as when the executable is started from Explorer. The Run tool window shows the output of Ahk2Exe and, when the program ends, its exit code.

The executable gets the script parameters and the working directory of the configuration. If compiling fails, the console shows the errors of Ahk2Exe (with links) and the executable is not started. While Ahk2Exe runs, a progress dialog is shown that can be cancelled.

A small console application. Run it with the option on and the terminal chosen.

#Requires AutoHotkey v2.0
;@Ahk2Exe-Base ..\v2\AutoHotkey64.exe
;@Ahk2Exe-ConsoleApp

stdout := FileOpen("*", "w")
stdin := FileOpen("*", "r")
stdout.Write("`e[32mYour name:`e[0m ")    ; green prompt
stdout.Read(0)                           ; flush
name := RTrim(stdin.ReadLine(), "`r`n")
stdout.WriteLine("Hello, " name "!")
ExitApp 0

Side effects and limits

  • An existing executable of the same name is overwritten. If it is still running, Ahk2Exe cannot write it and reports an error.
  • The plugin passes no /base and no output file; change those with the directives in the script.
  • The debugger always debugs the script, also with Compile with Ahk2Exe on; the console says so.
  • AutoHotkey v2 sets A_WorkingDir to the folder of the executable at startup; the working directory of the configuration is available as A_InitialWorkingDir.
  • Compiler errors are shown in the console only, not marked in the editor.
  • A compilation of the same script that is still running is not started a second time. After 120 seconds Ahk2Exe is stopped.
  • With the compression UPX, upx.exe must be in the folder of Ahk2Exe.
