;@ignore-next-line

Hides the parser errors of the next line. This is a pragma: AutoHotkey treats it as an ordinary comment.

;@ignore-next-line Reason

Parameters

Reason

Optional text explaining why the line is ignored. It has no effect.

Remarks

The parser of the plugin does not understand every construct AutoHotkey accepts, for example a call without parentheses whose first argument is a function (SetTimer () => ..., 100). Such a line is marked with "Syntax error". If the code is correct, the pragma hides these errors.

The next line is still parsed. Its parser errors are hidden, and the line is shown with a marked background (color Special: Unchecked code line in Settings > Editor > Color Scheme > AutoHotkey). Built-in names in this line are not colored, and reformatting does not change their case.

The pragma applies to exactly one line. Errors which follow from the ignored line in later lines remain visible, for example the closing brace of a block whose opening line was ignored. They are meant as a hint to rewrite the code in a form the parser understands.

The pragma itself gets a warning "Parser errors suppressed.", so that ignored lines are not forgotten. If the next line has no parser error at all, it gets a hint that the pragma is unnecessary instead.

Only errors of the plugin's parser are hidden. Errors reported by Validate with AutoHotkey stay visible.

Lines with comments only are not skipped: the pragma always refers to the line directly below it.

Examples

A call without parentheses whose first argument is a fat arrow function.

;@ignore-next-line the parser does not support this call form
SetTimer () => MsgBox("Time is up"), -1000

Without the pragma, the line can be rewritten with parentheses, which the parser understands:

SetTimer(() => MsgBox("Time is up"), -1000)
