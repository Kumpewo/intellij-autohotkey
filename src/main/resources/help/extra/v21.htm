AutoHotkey v2.1 (alpha)

Alpha: AutoHotkey v2.1 is still being developed; the current version is an alpha (the plugin follows v2.1-alpha.39). Its specification changes from one alpha to the next. The plugin implements v2.1 as closely to the current specification as it can, but this support is itself at an early stage: expect unexpected errors, missing features and differences from AutoHotkey, and expect parts of it to change together with AutoHotkey. AutoHotkey v2.0 is not affected: files of language level v2.0 are fully supported.

This chapter collects everything the plugin does for AutoHotkey v2.1. Modules, the largest new feature, have a page of their own.

Language level

Each file has a language level, AutoHotkey v2.0 or v2.1 (v2.1 is currently an alpha version). It comes from #Requires: if a part asks for 2.1 or later (#Requires AutoHotkey v2.1-alpha.39, >=2.1), the file is v2.1, otherwise v2.0. Files without #Requires use the setting Language level (default v2.0).

The status bar shows the level of the file in the editor: AHK v2.0, AHK v2.1, or AHK v1 for a file of another version, which the plugin does not parse. Its tooltip says where the level comes from; a click goes to the deciding #Requires line or, for the default level, opens the settings. A right-click on the status bar hides it. The Project view shows the level in grey after the name of each AutoHotkey file; the setting Show the language level in the Project view switches this off.

Choose v2.1 only for scripts that really use it; for everything else v2.0 is the stable choice.

Built-in names and help

In v2.1 files the plugin knows the new built-in names of v2.1-alpha.39 (for example ATan2, WinGetEnabled, A_HotIf, Struct, #Module, Error.Show), their parameter info and the help pages of that version.

New syntax

Of the new syntax of v2.1 the parser knows so far:

  • the operators a !~= b (not RegExMatch), x ??= y (maybe-assign) and the optional chain a?.b;
  • struct definitions struct Name { ... } (like a class; struct is a keyword only there, otherwise a normal name such as the class Struct);
  • mandatory parameters after optional ones (f(a?, b), f(a := 1, &b)); a variadic parameter (b*) may follow an optional one in v2.0 too;
  • modules: #Module Name and #Import [Export] Name [as Alias] [{ *, Name [as Alias], ... }]; inside the braces line breaks and comments are allowed. #Module is only allowed at the top level, #Import also directly in the body of a function (not in other blocks or a class body), as in AutoHotkey;
  • function definition expressions: x := f(a) { ... }, SetTimer(() { ... }, 100), also called directly (f() { ... }(1)). As in AutoHotkey the name must stand directly before ( (f () { ... } concatenates f with an anonymous function), the { must be on the line of the ) unless the function is enclosed in ( ), [ ] or { }, and in the head of if, while, loop, for, switch, catch and until a function expression must be enclosed in brackets (if f() { is a call followed by the block of the if). A function expression that forms a whole statement on its own ((a) { ... } at the start of a line, else f() { ... }) is an error; only after a hotkey or hotstring a named one is allowed (F1::f(hk) { ... }). The function is a normal function for the plugin: its name is found by navigation, completion and parameter info, its parameters and variables are local, and it uses the variables of an enclosing function (closure). Named function expressions appear in the structure view, anonymous ones do not;
  • typed properties in the body of a class or struct: x : Int32, cbSize : UInt32 := this.Size, several on one line (x : Int32, y : Int32, also mixed with fields such as y := 2), and union { ... } blocks of typed properties. The type is a class name, an expression in brackets, or a name with calls, index and member access (RECT, Int32[10], RECT.Ptr, CString(32, "UTF-8"), (expr)); an operator such as + or a string is an error, as in AutoHotkey. Outside a class body x : Int32 is not recognized (as in AutoHotkey). A union block contains only typed properties and stands directly in a class body; union { } without a typed property is a property named union. Typed properties are fields of the class: navigation, completion after this. or a declared type, Find Usages and Rename work as for x := 0. The formatter puts one space around the :.
  • Throw as a function in an expression: x := c ? 1 : throw(Error()), f := Throw; at the start of a statement throw stays the statement.

In a v2.0 file these are marked as errors ("Requires AutoHotkey v2.1", for parameters "Parameter default required"). Modules are separate namespaces for navigation, completion, Find Usages and Rename, and #Import finds module files (see Modules).

Running, validating and debugging with the alpha

  • Files of language level v2.1 are run, validated and debugged with the AutoHotkey v2.1 interpreter (the newest installed v2.1 unless one is set), always directly and never via the launcher, which does not know alpha versions that were only unpacked (see Running scripts).
  • Validation (/validate) uses this alpha. It may report errors you would not expect, or accept code that the plugin marks as an error and the other way round, because the alpha, the plugin and the help of v2.1 do not always agree. When AutoHotkey accepts code that the plugin marks, the mark becomes "Syntax error (AutoHotkey accepts this code)" (see Validating); the result of AutoHotkey counts. Please report such differences.
  • The debugger works with the v2.1 engine, which reports objects a little differently (inherited properties and getters as children, the prototype as Name.Prototype).
  • A new alpha can change the language. The plugin is checked against the alpha named above; with a newer one, keep an eye on validation.

Known limitations

Not supported yet:

  • Any syntax of v2.1 not listed under New syntax.
  • The type of a typed property is not used for completion (this.rc. after rc : RECT does not offer the fields of RECT), and it is not checked in detail (for example Int32? is accepted).
  • &x.y, IsSet(X?.Y) and Type(V?) have not been checked against AutoHotkey.
  • Modules: #Warn per module and embedded modules (#Import "*Resource") are not evaluated; in the debugger the Global node always shows the module of the innermost frame (see Modules).

Deliberate differences from v2.1-alpha.39:

  • Each file has its own language level. An included file does not take over the level of the file that includes it; AutoHotkey uses the mode that applies at the #Include line. Give included v2.1 files their own #Requires line.
  • #Include <Name>: the additional folder searched first is the folder of the including file; AutoHotkey uses the folder of the main script.
  • Accepted by the plugin although the alpha rejects or treats them differently: a? .b (space before the dot), #Import X{*} without a space, a function expression after case x: on the same line.
  • An empty #Import is an error for the plugin.
  • union { } without a typed property is a property named union.

See also the general known limitations, which apply to v2.1 files as well.
