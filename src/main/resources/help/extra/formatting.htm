Formatting and case adjustment

Reformat Code

Code > Reformat Code (Ctrl+Alt+L) formats the selection or, without a selection, the whole file. Ctrl+Alt+I only fixes the indent of the current lines. The options are under Settings > Editor > Code Style > AutoHotkey; every tab has a preview.

The formatter

  • indents blocks, the bodies of control structures and the lines of a switch (case at the level of switch, its statements one level deeper);
  • gives continuation lines of an expression the continuation indent; content between brackets that starts on a new line gets the normal indent: 
    result := Calculate(first,
        second)               ; continuation indent
values := [
    1, 2, 3                   ; normal indent
]
    All continuation lines of a statement get the same indent, also when the expressions are nested: 
    total := (shipping
        + price               ; price * quantity is nested in the addition,
        * quantity)           ; but both lines get one continuation indent
  • sets the spaces around operators, after commas and inside brackets according to the settings;
  • limits the number of consecutive blank lines;
  • indents block comments like the code around them; in a doc comment the lines starting with * follow the first line.

It never adds or removes line breaks, because the end of a line ends a statement in AutoHotkey. It never changes the space before ( or [ of a call either: f (x) is a concatenation of f and (x), not a call. Files with a syntax error are formatted as far as possible; files for another AutoHotkey version are not formatted at all.

Note: Lines the plugin's parser does not understand (see accepted syntax errors) may be changed in a way that changes their meaning. Check them after formatting, or exclude them with a selection.

Case adjustment

AutoHotkey ignores the case of keywords and built-in names; msgbox, MsgBox and MSGBOX are the same. The tab Case of the code style page lets Reformat Code write them in a uniform way.

Only words in their recognized role are changed: a property called length in length := 1 stays as it is, obj.IF too. Never changed are strings, comments, hotstrings, own names and names with a declared type, definitions, object keys, the line after ;@ignore-next-line and files for another AutoHotkey version. A word is only replaced if it differs in case alone. Ctrl+Z undoes the adjustment together with the formatting.

The keyword settings also apply to the completion: with lowercase it inserts if, otherwise If — even if the main switch is off.

if WINEXIST("ahk_class Notepad") AND a_index > 1
    winactivate
; becomes
If WinExist("ahk_class Notepad") and A_Index > 1
    WinActivate

Doc comments

The tab Doc Comments of the code style page lets Reformat Code rewrite doc comments /** ... */, like the JavaDoc settings in IntelliJ. It has a main switch Format doc comments when reformatting (default off); without it only the lines starting with * are aligned below the first line. Plain block comments are never changed. The preview on the right shows the effect of every switch.

Never changed: the code of @example, Markdown code blocks (``` or indented by 4), headings, tables and the end of a line with a hard break (two spaces or a backslash). A list item is wrapped with its further lines below its text. Words are never split, so a long URL may go past the margin, and a word that would change the meaning at the start of a line (@tag, -, #, 1.) stays at the end of the line before. Blank lines between paragraphs are kept (several become one); blank lines between tags follow the switches above.
