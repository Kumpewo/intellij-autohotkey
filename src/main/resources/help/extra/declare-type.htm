;@declare-type

Declares the class of one or more variables, so that the plugin knows their members. This is a pragma: AutoHotkey treats it as an ordinary comment.

;@declare-type Pattern as Class , Pattern as Class, ...

Parameters

Pattern

The names the declaration applies to. One of the following:

  • Name: exactly this name, e.g. myGui.
  • Prefix: all names starting with the prefix, e.g. btn* for btnOK and btnCancel.
  • Suffix: all names ending with the suffix, e.g. *Edit for nameEdit.

The wildcard * also matches nothing: *Edit covers edit as well. A pattern may contain only one wildcard, at its start or end; * alone and a*b are invalid.

Class

One of the following:

  • A built-in class, also a nested one: Gui, Map, Gui.Edit.
  • A class defined in the same file or in a file it includes, directly or through other included files (in files of language level v2.1 only directly), also a nested one: MyList, Outer.Inner.

If an own class has the same name as a built-in class, the built-in class is used.

Effect

For a declared name the plugin

  • shows the name in the color Special: Variable with declared type (Settings > Editor > Color Scheme > AutoHotkey);
  • offers only the members of the class and its base classes after the dot (myGui.), the class's own members first;
  • narrows the parameter info of method calls (myGui.Add() to the class and its base classes;
  • narrows the help of methods and properties with several help pages (Add of Gui and Menu) to the declared class.

Base classes are taken into account: a variable declared as Gui.Edit also knows the members of Gui.Control, Object and Any. An own class without extends has the base class Object.

Remarks

The declaration applies to the whole file in which it stands, no matter where it is placed. It never applies to other files, neither to included files nor to files including this one, with one exception: the pragmas of a directly included file named pragmas.ahk apply in the including file (see Pragmas).

Case does not matter, neither in the patterns nor in the class names.

A name may be covered by several patterns and thus have several classes; the members of all of them are offered.

A built-in name (e.g. a variable called Edit) keeps its built-in color if it is only covered by a pattern with a wildcard. Declare the exact name to give it the color of a declared variable.

The color is meant for variables. A name that is called (myFunc(), myFunc "x" or myFunc alone on a line) keeps its normal color, even if a pattern covers it. Where a name may be a variable as well as a function (x := myFunc, SetTimer myFunc), it gets the color.

Mistakes are marked in the comment: "Invalid pattern.", "'as' expected.", "Class expected.", "Unknown class." and "',' expected.".

Several pragmas may be used in one file; they add up.

Examples

Declares a GUI window and all edit controls whose names end with "Edit".

;@declare-type win as Gui, *Edit as Gui.Edit
win := Gui()
nameEdit := win.AddEdit()
nameEdit.Focus()   ; completion offers the members of Gui.Edit and its base classes

Declares variables of an own class derived from Array.

;@declare-type list* as ItemList
class ItemList extends Array {
    Last() => this[this.Length]
}
listA := ItemList()
listA.Last()   ; offers Last as well as Push, Pop ... of Array
