Doc comments

A doc comment describes your own function, method or class, like JavaDoc or JSDoc in other languages. It is a block comment that starts with /** and stands directly before the definition. The plugin shows it as quick documentation (Ctrl+Q or hovering with the mouse) wherever the name is used. For AutoHotkey it is an ordinary comment.

/**
 * Opens the box and counts the openings.
 *
 * The count is kept per box. Use **force** only in tests.
 * @param {String} name  name of the box
 * @param force  open even if the box is locked
 * @returns {Integer} the new number of openings
 * @throws Error if the box does not exist
 * @example
 *   count := OpenBox("tools")
 * @see CloseBox
 */
OpenBox(name, force := false) {
    ...
}

Where a doc comment counts

  • Only /** ... */. A plain block comment /* ... */ and line comments are not doc comments.
  • Between */ and the definition there may be spaces and one line break, but no empty line.
  • Functions, methods (also fat-arrow definitions like Twice(x) => x * 2) and classes have doc comments. Properties, fields, hotkeys and labels do not.
  • The leading * of each line is removed. The text before the first tag is the description, written in Markdown: `code`, **bold**, lists, code blocks.

Tags

A tag starts a line and continues on the following lines up to the next tag.

TagMeaning
@param [{Type}] name textA parameter. The name is written without &, * or ?. A type in braces ({Gui}, several with |: {Gui|Menu}) works like ;@declare-type for this parameter, but only inside the function: completion after name., parameter info, help and color.
@returns [{Type}] textThe return value (also @return). The type is only shown.
@throws textAn error the function throws.
@exampleExample code; the following lines are shown as written.
@see name|url [text]A link: to an own function, method or class (CloseBox, Box.Open), to the AutoHotkey help (MsgBox, Gui.Add) or to a web page.
@deprecated [text]The definition should no longer be used. Every use of the name is struck out, with the text as a hint.

Other words with @ are normal text.

The popup

The quick documentation shows the signature (as in the parameter info, with the class: Box.Open(name, [force := false])), the description, a section per tag and the file. It works on the definition itself and on every use: OpenBox(), obj.Open(), Box(), extends Box. Like Go to declaration, it matches by name in the file and its directly included files. An own definition takes precedence over the built-in help of the same name. If several definitions match (for example a method Open in two classes), the popup lists them; click one to see its documentation. Ctrl+hover shows the signature.

The doc comment also appears

  • in the completion list: Ctrl+Q on a suggestion of an own function, method or class;
  • in the parameter info: the @param text of the current parameter in a second line.

Writing doc comments

  • Type /** in the line above a definition and press Enter: the plugin closes the comment and adds one @param line per parameter and @returns if the function returns a value (return x or =>).
  • Enter inside a doc comment starts the new line with * .
  • Reformat Code indents the comment like the definition below it and aligns the lines starting with * under the first line. With the tab Doc Comments of the code style page it also aligns the @param lines, sets blank lines, wraps the text at the right margin and can sort, add or remove @param tags.
  • A @param without a parameter of that name and an unknown class in {...} are marked as warnings.
