Doc comments

A doc comment describes your own function, method, class, property or field, like JavaDoc or JSDoc in other languages. It is a block comment that starts with /** and stands directly before the definition (pragma lines such as ;@declare-member-type may stand in between). The plugin shows it as quick documentation (Ctrl+Q or hovering with the mouse) wherever the name is used. For AutoHotkey it is an ordinary comment.

/**
 * Opens the box and counts the openings.
 *
 * The count is kept per box. Use **force** only in tests.
 * @param {String} name  name of the box
 * @param force  open even if the box is locked
 * @returns {Integer} the new number of openings
 * @throws Error if the box does not exist
 * @example
 *   count := OpenBox("tools")
 * @see CloseBox
 */
OpenBox(name, force := false) {
    ...
}

Where a doc comment counts

  • Only /** ... */. A plain block comment /* ... */ and line comments are not doc comments.
  • Between */ and the definition there may be spaces and one line break, but no empty line.
  • Functions, methods (also fat-arrow definitions like Twice(x) => x * 2) and classes have doc comments. Properties and fields (count := 0, static count := 0) can be marked with @deprecated; the other tags and the popup are for functions, methods and classes. Hotkeys and labels have no doc comments.
  • The leading * of each line is removed. The text before the first tag is the description, written in Markdown: `code`, **bold**, lists, code blocks.

Tags

A tag starts a line and continues on the following lines up to the next tag.

TagMeaning
@param [{Type}] name textA parameter. The name is written without &, * or ?. A type in braces ({Gui}, several with |: {Gui|Menu}) works like ;@declare-type for this parameter, but only inside the function: completion after name., parameter info, help and color.
@returns [{Type}] textThe return value (also @return). The type is only shown.
@throws textAn error the function throws.
@exampleExample code; the following lines are shown as written.
@see name|url [text]A link: to an own function, method or class (CloseBox, Box.Open), to the AutoHotkey help (MsgBox, Gui.Add) or to a web page.
@deprecated [text]The definition should no longer be used. Every use of the name is struck out, with the text as a hint. This is the inspection Use of a deprecated definition (Settings > Editor > Inspections > AutoHotkey), so Code > Inspect Code lists all uses in a project.

The JSDoc tags @author, @since, @version, @todo, @license and @copyright are accepted and shown in the popup, each in a section of its own. Any other tag at the start of a line is probably a typo: it is marked as unknown (inspection Unknown doc comment tag), and Alt+Enter changes it to the most similar tag, for example @retruns to @returns. A word with @ inside the text (name@example.com) is normal text.

Typing @ at the start of a line offers the tags; after @param the completion offers the parameters that are not described yet.

The popup

The quick documentation shows the signature (as in the parameter info, with the class: Box.Open(name, [force := false])), the description, a section per tag and the file. It works on the definition itself and on every use: OpenBox(), obj.Open(), Box(), extends Box. Like Go to declaration, it matches by name in the file and the files it includes. An own definition takes precedence over the built-in help of the same name. If several definitions match (for example a method Open in two classes), the popup lists them; click one to see its documentation. After the dot of a name with a declared type or of this, only the members of that class and its base classes count. Ctrl+hover shows the signature.

For properties and fields the first line names the kind and the class (field ToolGui.logWriter, static field Box.count, property Box.Item[index] (get, set)); below it the declared type of an instance property or field (;@declare-member-type, ;@declare-type Class.member) and the doc comment, if there is one. Ctrl+hover shows field ToolGui.logWriter : LogWriter. A doc comment before a := 0, b := 0 describes both fields.

The doc comment also appears

  • in the completion list: Ctrl+Q on a suggestion of an own function, method or class;
  • in the parameter info: the @param text of the current parameter in a second line.

The name after @param belongs to the parameter: Ctrl+B on it leads to the parameter, renaming the parameter renames it as well, and Find Usages and the highlighting of occurrences show it.

A class name in {...} belongs to the class in the same way: Ctrl+B leads to it (for a built-in class to its help), Ctrl+Q shows its documentation, and renaming the class renames it as well.

Writing doc comments

  • Type /** in the line above a definition and press Enter: the plugin closes the comment and adds one @param line per parameter and @returns if the function returns a value (return x or =>). Before a property with parameters (Item[index]) it adds one @param line per parameter, before a field or another property only the description line.
  • Enter inside a doc comment starts the new line with * .
  • Reformat Code indents the comment like the definition below it and aligns the lines starting with * under the first line. With the tab Doc Comments of the code style page it also aligns the @param lines, sets blank lines, wraps the text at the right margin and can sort, add or remove @param tags.
  • A @param without a parameter of that name and an unknown class in {...} are marked as warnings.
