Navigation

Go to declaration

Ctrl+B or Ctrl+click on a name jumps to its definition. AutoHotkey has no static types, so the plugin matches names only, ignoring case. If several definitions match, a list lets you choose: first those of the current file, then those of the included files in the order of their #Include lines.

NameTarget
Free-standing (DoWork(), Counter)Functions that are not methods (also nested functions) and top-level classes. Inside a function a local variable or parameter leads to its first definition.
After the dot (obj.Next())Methods, properties, fields (count := 0 in a class body) and nested classes of all classes with that name. Without type analysis obj.__New offers every __New.
After extendsThe base class; in extends Outer.Inner Outer is the top-level class and Inner the class nested in it.
goto, break, continueThe label in the same function, hotkey or at the top level (goto Retry, goto "Retry", break Outer). A name in parentheses (goto(target)) is a variable.
#IncludeOpens the included file (see below).
Built-in name (MsgBox)If there is no own definition: the help popup, as with Ctrl+Q.

The search covers the file itself and the files it includes directly with #Include or #IncludeAgain, not the files included by those, and not the rest of the project. The same files are used by the completion and the parameter info.

Main script and a directly included file.

; main.ahk
#Include lib\tools.ahk
Log("started")          ; Ctrl+B jumps to Log in tools.ahk

; lib\tools.ahk
#Include helpers.ahk    ; functions in helpers.ahk are not visible from main.ahk
Log(text) {
    FileAppend text "`n", "app.log"
}

#Include files

Ctrl+B on the argument of #Include or #IncludeAgain opens the file. The plugin resolves the path like AutoHotkey:

  • <Name> is a library file Name.ahk searched in the folders Lib next to the script, Documents\AutoHotkey\Lib, and Lib of the AutoHotkey installation (for the launcher v2\Lib). If it is not found and the name contains _, the part before the first _ is tried. A subfolder is allowed: <v2\Tools>. In files of language level v2.1 the search follows AutoHotkey v2.1: the folder of the file comes first, each folder is searched for the exact name (Name, Name.txt) before Name.ahk, _ has no special meaning, and the standard library is Lib next to the v2.1 interpreter.
  • Other arguments are files or folders: with or without quotes, with *i, relative to the folder of the file or to the folder of an earlier #Include Folder in the same file.
  • Built-in variables in percent signs are resolved: %A_ScriptDir%, %A_LineFile%, %A_MyDocuments%, %A_AppData%, %A_ProgramFiles%, %A_Temp%, %A_AhkPath% and others. A_ScriptDir is the folder of the file with the #Include, because the plugin does not know the main script.
  • If the argument is a folder, a hint says so (such a line only sets the folder for the following #Include lines).

Library "AutoHotkey Lib"

The existing global library folders (Documents\AutoHotkey\Lib and Lib of the installation and of the v2.1 interpreter) are added to every project as the library AutoHotkey Lib; it appears under External Libraries in the project view. Files there are fully colored and checked when opened via Ctrl+B.

Note: Other files outside of the project (for example #Include ..\other\x.ahk) only get the basic colors (strings, numbers, comments, hotkeys), without the role colors and error checks. Add their folder to the project as a content root (File > Project Structure > Modules) if you edit them often. A library folder created while the IDE runs appears after a restart or a change on the settings page.

Local variables and parameters

Inside a function (also a method, a property, get/set, and a fat-arrow function (x) => x * 2) the plugin knows which names are local, following the rules of AutoHotkey v2 (AutoHotkey help, Functions: Local and Global Variables and Nested Functions):

  • Local are the parameters, names declared with local or static, and names that are assigned (x := 1, x += 1, x++), passed by reference (&x) or used as for and catch ... as variables - anywhere in the function, as AutoHotkey decides this when the script loads.
  • Not local are names that are only read (they may be global variables), names declared global, all names that are only assigned in an assume-global function (global alone as the first line), built-in variables, and the names of functions and classes (built-in or own) unless they are parameters or declared local/static.
  • Nested functions share the variables of the enclosing function that it has as parameters, declares or assigns, unless they declare the name themselves; a static nested function only shares static variables. A global declaration in the enclosing function applies to the nested functions as well.

For such a variable, Ctrl+B leads to its first definition (parameter, declaration or first assignment); completion, Find Usages, Rename and the highlighting of occurrences only look at the same variable, so a count in another function or a global count is not affected. Variables outside of functions (global variables) still work by name.

Two functions with a variable total, and a nested function that shares one.

Sum(values) {
    total := 0              ; local variable of Sum
    Add(v) => total += v    ; shares total and is a closure
    for v in values
        Add(v)
    return total
}
Average(values) {
    total := Sum(values)    ; another variable: renaming total in Sum leaves it alone
    return total / values.Length
}

Find Usages

Alt+F7 on a function, method, class, property, field or label (at its definition or at a use) lists its usages. Searched are the file of the definition and all AutoHotkey files of the project that include it with a direct #Include - exactly the places from which Ctrl+B leads to the definition. The matching follows navigation: by name, ignoring case, so a free-standing variable with the name of a function counts as well. Ctrl+B on a definition shows the same list. For a local variable or parameter only its function is searched.

Rename

Shift+F6 on a function, method, class, property, field or label (at its definition or at a use) renames it. The dialog always leads to a preview: all occurrences appear in the Find tool window, grouped by file. Exclude occurrences that belong to something else (Delete or Exclude in the context menu, also whole files), then click Do Refactor. Ctrl+Z undoes the rename in all files.

  • Searched are the file of the definition and all AutoHotkey files of the project that include it, directly or indirectly (a script that includes a file that includes the definition's file).
  • Occurrences are found by name, ignoring case, as for Find Usages; all of them get the spelling of the new name.
  • Search in comments and strings adds whole-word occurrences in comments and strings of these files, shown separately in the preview.
  • The new name must be a valid AutoHotkey name and no reserved word; if a function or class (or a member of the same class) with that name already exists, the dialog reports a conflict.
  • Local variables and parameters are renamed directly in the editor, without dialog and preview: type the new name, Enter applies it to all occurrences of the variable in its function (and in nested functions that share it) and, for a parameter, to its name after @param in the doc comment; Escape cancels.
  • Global variables are not renamed; for them use Replace in Files (see Limitations).
  • Where nothing can be renamed (a global variable, a built-in name, a keyword, a member without an own definition), a hint at the caret says why.

Why the preview matters and what no search can find: see Limitations.

Go to Symbol and Go to Class

Navigate > Symbol (Ctrl+Alt+Shift+N) searches the definitions of all AutoHotkey files of the project by name: functions, methods, classes, properties, fields, labels, hotkeys and hotstrings. Navigate > Class (Ctrl+N) lists only the classes. Both are also tabs of Search Everywhere (Shift twice).

  • Type the name, a part of it or its capitals (gwt finds GetWindowTitle), ignoring case. Members and nested classes can also be searched with their class: Box.Open, Outer.Inner.
  • Each entry shows the name with its classes (Box.Open(), Box.count, Start:, F1::, ::btw::) and the file. For a hotkey type its keys (F1, ^!a), for a hotstring its abbreviation (btw).
  • The library AutoHotkey Lib is searched only with Include non-project items (or pressing the shortcut twice).

Unlike Ctrl+B, this is a free search over the whole project: a function with the same name in another script appears as well, and you choose the entry. Go to declaration still only looks at the file and its directly included files.

Other ways to navigate

  • Ctrl+F12 shows the structure of the file as a popup with search; Alt+7 as a tool window.
  • Click an entry of the breadcrumbs or a sticky line to jump to the enclosing construct.
  • Ctrl+Shift+M jumps to the matching brace.
