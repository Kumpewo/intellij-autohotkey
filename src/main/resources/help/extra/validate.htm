Validating with AutoHotkey

The plugin's parser does not know every construct, and some errors can only be found by AutoHotkey itself, for example a missing #Include file, a duplicate function or a call with the wrong number of parameters. Validate with AutoHotkey lets AutoHotkey load the script without running it (/validate) and shows the result in the IDE.

Start

  • Code > Validate with AutoHotkey, Alt+Shift+V, or the context menu of the editor and of the project view.
  • Automatically after Reformat Code or after saving, depending on the setting.

Requirement: AutoHotkey v2 installed (the same program as for running).

Which script is validated

If an AutoHotkey run configuration is selected in the toolbar and the current file is its script or is included by it with #Include (also indirectly), that script (the main script) is validated. An included file alone usually fails, because it lacks the definitions of the main script. In all other cases the current file is validated: without such a run configuration, and for a file that does not belong to it, for example in a project that collects many small scripts. Without a current file (e.g. a folder selected in the project view) the script of the run configuration is used.

What happens

  1. All modified AutoHotkey files are saved.
  2. The plugin writes a copy of the script next to it, name.~validate.ahk, with the line #Warn All, StdOut appended. Being the last #Warn, it overrides the warning mode of the script, so a warning can never open a message box and block the validation. The line numbers stay the same.
  3. AutoHotkey runs in the background: program /ErrorStdOut /validate copy, in the folder of the script (so A_ScriptDir, Lib folders and relative #Include paths are right).
  4. The copy is deleted. In the output, its name is replaced by the name of the original.

Result

  • The console in the Run tool window shows "Validating name.ahk...", the output of AutoHotkey and a summary: green if AutoHotkey found no errors, red for an error or if AutoHotkey could not finish. File names with line numbers are links. Manual validations always show the console, automatic ones only if there is an error. Reformat Code on an AutoHotkey file empties the console, so that no outdated output stays until the next validation.
  • The line of the error is marked in the editor ("AutoHotkey: message"), also in an included file. The mark disappears as soon as the file is changed.
  • Warnings (#Warn, e.g. a variable that is never assigned) are listed in the console and counted in the summary, but are not errors and are not marked in the editor.
  • AutoHotkey stops at the first error; fix it and validate again.

Form of the console output for a script with an error; C:\Scripts\main.ahk (12) is a link.

Validating main.ahk...
C:\Scripts\main.ahk (12) : ==> error message of AutoHotkey
     Specifically: the code concerned

AutoHotkey reports an error (exit code 2).

AutoHotkey accepts what the plugin rejects

If AutoHotkey accepts the file but the plugin's parser reports syntax errors in it, the plugin does not understand these lines. Their errors are then shown as "Syntax error (AutoHotkey accepts this code)", and the console says how many there are. Reformatting such lines may change their meaning; consider ;@ignore-next-line or a different way of writing them. The plugin's own messages (Unexpected '}' ...) stay unchanged.

Side effects and limits

  • The temporary copy name.~validate.ahk exists for a moment in the folder of the script. Tools that watch the folder (version control, file synchronization) may see it.
  • With the setting Also when a file is saved, the automatic saving of the IDE (when it loses focus, before a run ...) also starts a validation. Saves by the validation itself do not. A validation of the same script that is still running is not started a second time.
  • Only load errors are found, no runtime errors.
  • If AutoHotkey does not finish within 15 seconds (for example because the script shows a dialog while loading), the plugin ends it and says so in the console.
