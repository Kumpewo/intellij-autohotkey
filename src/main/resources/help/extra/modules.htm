Modules (AutoHotkey v2.1)

Alpha: modules belong to AutoHotkey v2.1, which is still an alpha. The plugin follows the specification of v2.1-alpha.39 as closely as it can, but it is likely to change; see AutoHotkey v2.1 (alpha).

AutoHotkey v2.1 splits a script into modules: each module has its own global variables, functions and classes. #Module Name starts a module, #Import makes another module or some of its names usable. The plugin evaluates modules in files with the language level v2.1; in v2.0 files #Module and #Import are errors and the file and its included files are one namespace.

#Requires AutoHotkey v2.1-alpha.39
#Import Tools                  ; the module Tools (below or Tools.ahk)
#Import Tools {Clamp as Fit}   ; one function under another name
#Import Shapes {*}             ; everything Shapes offers
MsgBox Tools.Clamp(5, 1, 3) " " Fit(0, 1, 3) " " Area(2)

#Module Tools
Clamp(v, lo, hi) => Min(Max(v, lo), hi)

#Module Shapes
Area(r) => 3.14159 * r * r

Namespaces

The code up to the first #Module is the module __Main; each #Module Name starts the module Name (or reopens it) up to the next #Module or the end of the file. A file included with #Include belongs to the module of the #Include line. A free-standing name (Clamp(), MyClass, extends Base) refers, in this order, to

  1. a function or class of the own module,
  2. a name the module imports explicitly: #Import X gives X (the module), #Import X as Y gives Y, #Import X {F, G as H} gives F and H,
  3. a name of a wildcard import #Import X {*}: what X defines and does not start with _, plus what X imports with #Import Export ...; the last wildcard import wins.

After a module (Tools.Clamp, Y.MyClass, extends X.Base) a name is what the module defines or imports, also names starting with _. Global variables of a module are reached only through an import (X.Counter, #Import X {Counter}): Ctrl+B goes to the first assignment or global declaration. Free-standing global variables still have no navigation. #Import AHK gives the built-in module: AHK.MsgBox goes to the help of MsgBox.

Module files

A module that is not a #Module of the file or of a file it includes is loaded from a file. As in AutoHotkey the plugin searches the folder of the file with the #Import, the folder of the module's file, then the folders of the environment variable AhkLibPath (separated by ;, as the IDE sees it) or, without it, the user library (Documents\AutoHotkey\Lib) and the standard library (Lib next to the v2.1 interpreter). In each folder it tries Name, Name\__Init.ahk and Name.ahk. #Import "Path:Name" uses the #Module Name of that file. The plugin does not know the main script, so the folder of the file counts as A_ScriptDir. AhkLibPath also applies to #Include <Name> in v2.1 files.

Ctrl+B on the module name of an #Import opens the #Module or the module file; on a name in the braces it goes to the definition in the module.

In the editor

  • Completion offers the functions and classes of the own module and the imported names; after X. only what module X offers, after AHK. the built-in names. After #Import it offers the module names (AHK, the modules of the file and its includes, module files of the search path), in the braces the names of that module.
  • Parameter info shows the imported function, also for X.F(.
  • Find Usages and Rename also search the files that import the file of the definition. A #Module and an alias after as can be renamed (with their uses); renaming an exported function also changes X.F and {F} in importing files, an alias stays. A module file is not renamed with its imports.
  • Highlighting: a built-in function or class that the module defines itself or imports (for example an own MsgBox) is not colored as built-in in that module; AHK.MsgBox keeps the built-in color.
  • Structure view and folding: a file with #Module shows the definitions of __Main first, then one node per module; each module section can be folded.

Checks

  • Error Module not found: the module is neither a #Module of the file and its includes nor a file in the search path (as AutoHotkey reports when it loads the script).
  • Error when a name that an #Import at the top level adds (the module name, the alias, a name in the braces) is also a function, class or global variable of the module; AutoHotkey refuses to load such a script.
  • Warning when a name in the braces is not in the module. AutoHotkey accepts this, the name simply stays unset.

Limitations

  • #Warn per module and embedded modules (#Import "*Resource") are not evaluated.
  • In the debugger the Global node always shows the globals of the module of the innermost frame, also when an outer frame of another module is selected; the AutoHotkey engine answers that way.
