Help

Quick documentation (popup)

Ctrl+Q, or resting the mouse on a name, shows the help page of a built-in variable, function, class, method, property, directive or keyword as a popup. Links in the page open further pages in the same popup; the arrows at the top go back and forward.

  • The page is chosen by the role of the word, like the colors: Gui.Button shows the page of the nested class, btn.Text the page of the property.
  • If a name has several pages (Add of Gui, Menu, Gui.ListView ...), the popup lists them; a click opens one. If the class of the object is known (a built-in class left of the dot, or a declared type including its base classes), only the matching page is shown.
  • Anywhere in a pragma comment (;@declare-type ...) the popup shows the page of that pragma.
  • Ctrl+B on a built-in name without own definition opens the same popup.
  • For your own functions, methods and classes the popup shows their signature and doc comment; an own definition takes precedence over a built-in page of the same name.

Note: The pages of the popup are part of the plugin. They are currently those of AutoHotkey v2.0.31, in files with the language level v2.1 those of v2.1-alpha.39, no matter which version is installed.

External help

Shift+F1 (View > External Documentation) or the link at the bottom of the popup opens the topic under the caret in a separate help viewer. If there are several topics, choose one from a list first.

  • AutoHotkey topics open by default in hh.exe (the help viewer of Windows) with the AutoHotkey.chm of your AutoHotkey installation, so they match the installed version. The file is searched next to the AutoHotkey program from the settings; for the launcher UX\AutoHotkeyUX.exe in v2\ and in the main folder of the installation.
  • Another program can be set under Settings > Languages & Frameworks > AutoHotkey > External help, see Settings.
  • Pages of the plugin (the pragmas and this manual) always open in hh.exe with the plugin's own help file. hh.exe cannot read files inside the plugin, so the file is copied to the temporary folder first (%TEMP%\intellij-autohotkey\extra-checksum.chm, reused until the plugin changes). The command line from the settings does not apply to them.

Help on compiler directives

Ctrl+Q anywhere in a compiler directive ;@Ahk2Exe-... shows the page "Script Compiler Directives" of the AutoHotkey help, Shift+F1 opens it in the external help. All directives share this one page. A disabled directive (;;@Ahk2Exe-...) is an ordinary comment.

Opening the AutoHotkey help

Help > AutoHotkey v2.0 Help and Help > AutoHotkey v2.1 Help open the help of that version at its start page: hh.exe with the AutoHotkey.chm of your AutoHotkey installation (v2.0) or the one next to the AutoHotkey v2.1 interpreter (v2.1), or the program of the external help setting with the key /docs/index.htm. Without an AutoHotkey.chm, the copy of the help that ships with the plugin is copied to %TEMP%\intellij-autohotkey\docs-2.0\ (or docs-2.1\) and opened in the default web browser.

This manual

Help > AutoHotkey Plugin Manual and the link at the bottom of the AutoHotkey settings page open this manual in hh.exe. If the plugin was built without its help file, the pages are copied to %TEMP%\intellij-autohotkey\manual\ and opened in the default web browser.
