settings.ahk-v2-plugin.ini - settings of the AutoHotkey v2 plugin for the tool of this project

One tool = one project: this file lies in the project root and is used by "Code > Deploy to Local Target..." and, for [SetVersion] only, by "Code > Set Version..." (which also works without this file). Details: Help > AutoHotkey Plugin Manual, page "Deploying tools and setting versions".

settings.ahk-v2-plugin.ini - settings of the AutoHotkey v2 plugin for a library project

One library = one project: "Code > Deploy to Local Target..." copies the files of [Install] into the user library folder, where #Include <Name> finds them, and "Code > Set Version..." sets their version. Edit the library only here and deploy it: the copies in the library folder are read-only in the IDE and lead back to this project. Details: Help > AutoHotkey Plugin Manual, pages "Deploying tools and setting versions" and "Libraries".

Format: lines key=value in sections. Comments are lines starting with ";" (spaces before it are allowed); a ";" later in a line is part of the value. Section and key names are case-insensitive. Values may be enclosed in double quotes, which are removed. Every key, and every source in a section, may appear only once.

Variables: the folder variables of AutoHotkey (%A_MyDocuments%, %A_AppData%, %A_Desktop%, %A_ProgramFiles%, %A_Temp% ...), %LIBRARY_PROJECTS% (the setting "Library projects folder") and %% for a percent sign; environment variables such as %USERPROFILE% are not resolved.

Lines starting with ";;" and a space are explanations, which the links above the editor remove and restore. Lines starting with a single ";" are options that are commented out, so their defaults apply. A commented-out switch shows the value you set to change it (the default is named in its explanation); remove the ";" to use an option.

Absolute folder for relative targets, usable as %DESTINATION% in targets and in Message. Without it all targets must be absolute. For a library: the user library folder that #Include <Name> searches; subfolders such as v2\ belong in the targets below, so that one project can deploy into several of them.

; the user library folder (for libraries)
Destination=%A_MyDocuments%\AutoHotkey\Lib

Text shown in the confirmation before anything is copied. `n is a line break; variables and %DESTINATION% are resolved (%DESTINATION% needs Destination), and {project-name} is the folder name of this project. Often used with GenerateOverview=no.

yes: show the destination, the compile step and the lines of [Install] and [InstallIfMissing] in the confirmation. Default: yes; no shows only the message (or a short question).

Comment lines written at the start of the copies, so that a copy tells where its source is (e.g. for a library). Only the files of [Install] get it: all AutoHotkey files (.ahk, .ah2, .ahk2) automatically, other files only if [AddBanner] includes them, which can also exclude AutoHotkey files. Default: none. Value:

  • the text itself (`n starts a new line),
  • a built-in template (@standard, @library),
  • file:<path> (a text file, relative to the project root) or
  • find:<name> (the text file <name> in the project root or the nearest folder above it, e.g. one banner.txt for all projects in a folder).

In the text, {project-name} is the folder name of this project, {project-path} its full path, {source-name} the file name of the source, {source-relative} its path relative to the project root, {source-path} its full path, {version} its version line, {commit} the Git commit (+ = uncommitted changes), {timestamp} the time of the deployment, {computer} the name of this computer and {include} the line #Include <...> of a copy in a Lib folder; a line whose placeholders are all empty is left out.

With {version} in the text, the copy loses its own version line (except a script with ;@Ahk2Exe-Base). Characters other than ASCII are only written into files with a byte order mark (UTF-8 or UTF-16); elsewhere they become _.

; built-in template for tools
Banner=@standard
; built-in template for libraries
Banner=@library
; the nearest banner.txt in the project root or above
Banner=find:banner.txt
; a text file of the project
Banner=file:texts\banner.txt
; the text itself, here with two lines
Banner=Deployed from {project-path}`nVersion {version}

yes: copy all files in one process with administrator rights (one UAC prompt). Needed for protected folders such as C:\Program Files. The plugin does not find this out by itself. Default: no.

yes: before copying, compile every executable named in [Install] and [InstallIfMissing] (a source ending in .exe, without wildcards) from the script of the same name next to it, e.g. MyTool.exe from MyTool.ahk. Each script needs a line ;@Ahk2Exe-Base; a missing line or a compilation error stops the deployment before anything is copied. An executable without such a script is just copied. no: the executables are copied as they are; the confirmation warns if one is older than the scripts next to it. Default: yes.

yes: the copies tell where they come from: the built-in banners name the full path of this project and the name of this computer, and an executable of [Install] compiled from a script of the same name next to it carries both as text at its end (ProjectPath, ProjectComputer), so that tools can find the project of an .exe. The executable in the project is not changed. Set it to no if you give the copies to others and do not want to disclose this. Own banner texts and banner files are not affected. Default: yes.

Lines source=target; existing targets are replaced.

Source: a file path that always starts at the project root (also without a leading \), no ..; * and ? are allowed in the file name, not in folder names.

Target: absolute or relative to Destination. It is a folder (the file keeps its name) if it ends with \ or /, is . or .., is Destination itself, already exists as a folder, or if the source has a wildcard; otherwise it is the new file name. Missing folders are created. Two lines (also of [InstallIfMissing]) must not give the same target. For several targets of one file use wildcards: MyTool.exe=dest1, MyTool.ex?=dest2.

A tool with a GUI and a console variant lists both executables.

; deploy all files of a folder into a subfolder of Destination
pictures\*=pictures\
; deploy and rename a file
main.exe=MyTool.exe

Like [Install], but a target that exists already is skipped (for configuration files you may have changed). These files never get a banner: the copy belongs to the user from then on.

; provide defaults, do not overwrite the target
config.ini=%A_AppData%\configs\MyTool.ini

Lines files=folder: before copying, Deploy moves leftovers of earlier deployments to the Recycle Bin (risky: a second confirmation lists every file). Folder: absolute or relative to Destination. Files: relative to that folder, * and ? in the file name; only files, not in subfolders. A file this deployment writes is an error.

; delete a formerly deployed file from its wrong place (protected folder: needs RequiresAdmin=yes)
MyTool.exe=C:\Program Files\wrong_place
; delete a formerly deployed file after renaming the source
OldTool.exe=.
; be careful with wildcards
*.*=C:\better_not_to_use__Windows__here

Lines selector=value for Banner. The selector is written like a line of .gitignore, relative to the project root: *.cmd matches in every folder, /x.ahk and lib/*.ahk only from the root, a trailing \ or / names a folder with everything below it; ** matches any number of folders. The last matching line wins. Values:

  • yes: the file gets the banner, in the comment of its type (e.g. ; for .ahk and .ini, # for .py and .ps1, // for .js and .cs, :: for .cmd, <!-- --> for .html and .md, /* */ for .css; all known types are listed in the manual); for a type without a known comment, yes is an error that asks for line: or block:;
  • no: no banner;
  • line:<start> [<end>]: every line in this comment, e.g. line:REM or line:<!-- -->;
  • block:<start> <end>: one block comment, e.g. block:/* */.

Binary files (.exe, .dll, .png ...) and the files of [InstallIfMissing] (meant to be changed by the user) never get a banner. The banner shifts the line numbers of the copy; "Open Library Project" takes this into account. Without Banner, deploying AutoHotkey files shows a warning; *.ahk=no says that they are meant to be deployed without a banner.

AutoHotkey files have yes by default, so the commented-out lines show the opposite.

; add banners to all batch files
*.bat=yes
*.cmd=yes
; but not to this one
this_one.bat=no

Lines selector=value for "Code > Set Version...", with selectors and values as in [AddBanner]. Every AutoHotkey file (.ahk, .ah2, .ahk2) of the project gets the new version unless a line excludes it with no (e.g. experiments or old variants): in the line ;@Ahk2Exe-SetVersion of a script with ;@Ahk2Exe-Base, in the line ;@SetVersion of any other; a missing line is added. Other files only by a line with yes; they get @SetVersion in the comment of their type.

This only concerns the version lines: commit and tag still need every file of the project to be versioned or ignored by Git. To keep files out of the commit, list them in .gitignore. The last matching line wins, so exclusions come after the lines that include files.

AutoHotkey files have yes by default, so the commented-out lines show the opposite.

; add version codes to batch files
*.bat=yes
*.cmd=yes
; but not to this one
this_one.bat=no
; and not to files in test or scratch
test\=no
scratch\=no
